РАЗДЕЛ 1

Что такое новая система плагинов?

В тестовой ветке игры разработчики из FakeFish Games (при ключевом участии Evil Factory) добавили встроенную поддержку скомпилированных C#-плагинов. Больше не требуются сторонние костыли, инжекторы или динамическая перекомпиляция скриптов через LuaCs — теперь Barotrauma нативно загружает предварительно скомпилированные `.dll` сборки через изолированный AssemblyLoadContext.

⚡

Почему это меняет всё?

  • Официальная поддержка: Никаких патчей `Barotrauma.exe` сторонними программами.
  • Максимальная скорость: Код компилируется вашим IDE напрямую в машинный код через JIT .NET 8.
  • Доступ к ядру: Пакеты Barotrauma.ReferenceAssemblies.Vanilla.Publicized открывают доступ к приватным полям игры без Reflection (требует атрибута IgnoresAccessChecksTo во избежание FieldAccessException в рантайме .NET 8).
  • Сетевой стек: Встроенные механизмы передачи кастомных сообщений между клиентом и сервером.
⚠️

Важное отличие от классических XML-модов

C# плагин может изменять базовое поведение игры, физику, сетевые пакеты и генерировать свой интерфейс. Однако он требует осторожности: если плагин запустит бесконечный поток или не очистит ссылки при выгрузке, игра не сможет выгрузить память сборки (Assembly Unload Leak). В руководстве подробно описано, как этого избегать.

Быстрый старт: пошаговая инструкция

Шаг 1

Склонируйте шаблон BaseBaroPlugin

Используйте готовый шаблон от FakeFish Games со всеми настроенными ссылками на NuGet:

git clone https://github.com/FakeFishGames/BaseBaroPlugin.git MyFirstPlugin
cd MyFirstPlugin
Шаг 2

Задайте имя плагина в BuildData.props

Откройте файл BuildData.props в корне проекта и измените ModName:

<Project>
  <PropertyGroup>
    <!-- Без пробелов, русских букв и спецсимволов! -->
    <ModName>MyFirstPlugin</ModName>
    <RepositoryURL>https://github.com/YourName/MyFirstPlugin</RepositoryURL>

    <!-- Поставьте true для доступа к приватным полям игры без Reflection -->
    <UsePublicizedAssemblies>false</UsePublicizedAssemblies>
  </PropertyGroup>

  <Import Project="UserBuildData.props" />
</Project>
⚠️ Критически важно: Обязательные метаданные сборки (Authors и Version)
При загрузке плагина движок Barotrauma строго проверяет наличие автора и версии. Если метаданные отсутствуют, игра выдаст ошибку Plugin ... is missing metadata: Authors и откажется запускать плагин!
Убедитесь, что в SharedSource/AssemblyInfo.cs или вашем .csproj указаны автор и версия игры: 
[assembly: System.Reflection.AssemblyCompany("ВашНикнейм")]
[assembly: System.Reflection.AssemblyVersion("1.0.0.0")]
[assembly: Barotrauma.PluginGameVersion("1.15.19.0")]

// ВНИМАНИЕ: Если UsePublicizedAssemblies=true, ОБЯЗАТЕЛЬНО добавьте атрибуты ниже,
// иначе в рантайме .NET 8 игра упадет с фатальной ошибкой System.FieldAccessException:
[assembly: System.Runtime.CompilerServices.IgnoresAccessChecksTo("Barotrauma")]
[assembly: System.Runtime.CompilerServices.IgnoresAccessChecksTo("BarotraumaCore")]
Шаг 3

Настройте путь к игре в UserBuildData.props

Скопируйте UserBuildData.props.example и назовите файл UserBuildData.props. Внутри укажите путь к папке LocalMods вашей Barotrauma:

<Project>
  <PropertyGroup>
    <!-- Путь к LocalMods игры. При каждой сборке файлы мода скопируются сюда автоматически -->
    <ModDeployDir>C:\Program Files (x86)\Steam\steamapps\common\Barotrauma\LocalMods</ModDeployDir>
  </PropertyGroup>
</Project>
Шаг 4

Откройте WindowsSolution.sln и запустите игру с отладкой

Откройте WindowsSolution.sln в вашей IDE. В меню запуска выберите профиль "Launch Barotrauma" и нажмите F5.

IDE скомпилирует плагин, разложит файлы в LocalMods и запустит Barotrauma с подключенным отладчиком!

РАЗДЕЛ 4

Архитектура папок и разделение кода

Шаблон использует модульное разделение на клиентский, серверный и общий код:

📁 SharedProject / SharedSource / Plugin.cs
Общий код для клиента и сервера. Здесь находится реализация IBarotraumaPlugin, регистрация сервисов, общих сущностей и физики. Для специфичных блоков можно использовать директивы #if CLIENT и #if SERVER.
📁 ClientProject / ClientSource / PluginClient.cs
Клиентский код. Интерфейс (GUI), визуальные эффекты, частицы, звуки, рендер, обработка клавиатуры игрока. Компилируется с флагом CLIENT в $(ModName)Client.dll.
📁 ServerProject / ServerSource / PluginServer.cs
Серверный код. Авторитарная логика выделенного сервера, античит, обработка прав игроков, сохранение состояния. Компилируется в $(ModName)Server.dll.
📁 ContentPackageBuilder / Content /
Пакет мода. Хранилище ваших XML файлов, спрайтов, предметов и префабов. При компиляции автоматически копируется в LocalMods/$(ModName)/Content.
📁 PluginToolbox /
Утилита компиляции. Автоматизирует мультиплатформенную компиляцию всех 6 проектов (Windows/Linux/Mac для Client/Server) одной командой для отправки в Steam Workshop.
РАЗДЕЛ 5

Манифесты: filelist.xml и PluginInfo.xml

В файле filelist.xml объявляется пакет контента. Появился новый тег <PluginInfo>:

<?xml version="1.0" encoding="UTF-8" ?>
<ContentPackage name="%ModName%">
  <!-- Указывает движку, что мод содержит нативный C# плагин -->
  <PluginInfo file="%ModDir%/PluginInfo.xml" />

  <!-- Стандартные файлы контента мода -->
  <Item file="%ModDir%/Content/Items.xml" />
</ContentPackage>

В PluginInfo.xml указываются пути к `.dll` файлам для каждой операционной системы:

<?xml version="1.0" encoding="UTF-8" ?>
<PluginInfos notsyncedinmultiplayer="false">
  <!-- Windows сборки -->
  <MainAssemblyInfo assemblypath="%ModDir%/Windows/%ModName%Server.dll" platforms="Windows" targets="Server" />
  <MainAssemblyInfo assemblypath="%ModDir%/Windows/%ModName%Client.dll" platforms="Windows" targets="Client" />

  <!-- Linux сборки -->
  <MainAssemblyInfo assemblypath="%ModDir%/Linux/%ModName%Server.dll" platforms="Linux" targets="Server" />
  <MainAssemblyInfo assemblypath="%ModDir%/Linux/%ModName%Client.dll" platforms="Linux" targets="Client" />

  <!-- macOS сборки -->
  <MainAssemblyInfo assemblypath="%ModDir%/Mac/%ModName%Server.dll" platforms="Mac" targets="Server" />
  <MainAssemblyInfo assemblypath="%ModDir%/Mac/%ModName%Client.dll" platforms="Mac" targets="Client" />
</PluginInfos>
Совет: Установите notsyncedinmultiplayer="true", если ваш мод чисто клиентский (кастомный UI, бинды клавиш, счетчики) и игроки могут заходить с ним на любые сервера без требования наличия мода на сервере.

Жизненный цикл плагина (IBarotraumaPlugin)

Каждый плагин реализует интерфейс IBarotraumaPlugin с тремя ключевыми методами:

using Barotrauma;
using Barotrauma.Plugins;
using Microsoft.Xna.Framework;

namespace MyAwesomeMod;

public partial class Plugin : IBarotraumaPlugin
{
    // Сервисы движка получаем через статический провайдер
    public static readonly IDebugConsole DebugConsole = PluginServiceProvider.GetService<IDebugConsole>();

    /// <summary>
    /// 1. Вызывается сразу при загрузке сборки в память.
    /// Идеально для регистрации хуков, компонентов, настроек и патчей Harmony.
    /// </summary>
    public void Init()
    {
        DebugConsole.NewMessage("Плагин загружен!", Color.Lime);
        InitProjectSpecific(); // Вызов клиентской или серверной реализации
    }

    public partial void InitProjectSpecific();

    /// <summary>
    /// 2. Вызывается после того, как все XML-файлы и пакеты контента загружены.
    /// Здесь безопасно читать ItemPrefab.Prefabs, локации и субмарины.
    /// </summary>
    public void OnContentLoaded()
    {
        
    }

    /// <summary>
    /// 3. Вызывается при отключении плагина, смене модов или выходе.
    /// ОБЯЗАТЕЛЬНО останавливайте потоки и очищайте подписки на события!
    /// </summary>
    public void Dispose()
    {
        DebugConsole.NewMessage("Плагин выгружен.", Color.OrangeRed);
    }
}
📁

Разрешение путей контента (%ModDir%) в C# коде

В XML-файлах часто пишется путь вида %ModDir%/Content/file.png. Если вы передаёте такой путь в свой C#-код, стандартный метод File.Exists("%ModDir%/...") вернёт false! Для получения реального абсолютного пути к файлу на диске используйте встроенный API движка: 

// 1. Быстрое разрешение через ContentPath движка:
string realPath = ContentPath.FromRaw(rawXmlPath).Value;

// 2. Если файл находится в другом моде или пакете контента:
if (!File.Exists(realPath) && ContentPackageManager.AllPackages != null)
{
    string subPath = rawXmlPath.Replace("%ModDir%/", "").Replace("%ModDir%\\", "").TrimStart('/', '\\');
    foreach (var pkg in ContentPackageManager.AllPackages)
    {
        if (pkg?.Dir != null)
        {
            string candidate = Path.Combine(pkg.Dir, subPath);
            if (File.Exists(candidate)) { realPath = Path.GetFullPath(candidate); break; }
        }
    }
}

Кастомный компонент предмета (ItemComponent)

Создание компонента предмета с собственной физикой, поведением в реальном времени и параметрами в XML.

using Barotrauma;
using Barotrauma.Items.Components;
using Microsoft.Xna.Framework;

namespace MyAwesomeMod;

public class SpinnerComponent : ItemComponent
{
    // Атрибут [Serialize] связывает XML-атрибут с C# свойством
    [Serialize(500f, IsPropertySaveable.Yes, "Сила кручения предмета")]
    public float SpinForce { get; private set; }

    public SpinnerComponent(Item item, ContentXElement element) : base(item, element)
    {
        IsActive = true;
    }

    public override void Update(float deltaTime, Camera cam)
    {
        // Применяем крутящий момент к физическому телу предмета каждый кадр
        if (item.body != null)
        {
            item.body.ApplyTorque(SpinForce * deltaTime);
        }
    }

    protected override void RemoveComponentSpecific()
    {
        // Очистка при уничтожении предмета
    }
}

Кастомное действие для StatusEffect

Создание собственного тега действия внутри <StatusEffect> (например, отправка оповещения, вызов подкрепления или телепортация).

using Barotrauma;
using Barotrauma.Plugins;
using System.Xml.Linq;

namespace MyAwesomeMod;

public class BroadcastStatusEffectAction : IStatusEffectAction
{
    private readonly string _message;

    public BroadcastStatusEffectAction(StatusEffect statusEffect, XElement element)
    {
        _message = element.GetAttributeString("message", "Внимание!");
    }

    public void Apply(StatusEffectParams effectParams)
    {
        Character? user = effectParams.Targets.OfType<Character>().FirstOrDefault();
        string fullMessage = user != null ? $"{user.Name}: {_message}" : _message;

#if SERVER
        GameMain.Server.SendChatMessage(fullMessage, ChatMessageType.ServerMessageBoxInGame);
#elif CLIENT
        if (GameMain.NetworkMember is null) // Одиночная игра
        {
            new GUIMessageBox("Сообщение", fullMessage, type: GUIMessageBox.Type.InGame);
        }
#endif
    }
}

// Регистрация в Plugin.Init():
var seService = PluginServiceProvider.GetService<IStatusEffectService>();
seService.RegisterAction(new StatusEffectActionFactory("Broadcast", 
    (statusEffect, element) => new BroadcastStatusEffectAction(statusEffect, element)));
<Item name="Клаксон тревоги" identifier="alarmhorn">
  <RangedWeapon reload="1">
    <StatusEffect type="OnUse" target="Character">
      <!-- Наше кастомное C# действие! -->
      <Broadcast message="СРОЧНО ВСЕМ НА БОЕВЫЕ ПОСТЫ!" />
    </StatusEffect>
  </RangedWeapon>
</Item>
⚠️ Ловушка с падением FPS при использовании в афликшенах:
Внимание: если кастомное действие вызывается внутри <Affliction><Effect>, Barotrauma выполняет блок <StatusEffect> каждый тиковый кадр (60 раз в секунду) всё время, пока сила эффекта находится в диапазоне minstrength..maxstrength.
Если ваш IStatusEffectAction воспроизводит видео, спавнит звуки или выделяет неуправляемые ресурсы, всегда делайте проверку состояния или кулдаун: 
// Защита от спама 60 вызовов в секунду:
if (_isPlaying || _cooldownTimer > 0f) { return; }
Без этой проверки игра каждую секунду попытается создать десятки параллельных ресурсов, что мгновенно просадит FPS до 1 и приведет к зависанию!

Сетевой обмен Клиент ↔ Сервер (IGameNetwork)

Строго типизированная передача сетевых сообщений без ручной сериализации байтов.

using Barotrauma;
using Barotrauma.Networking;
using Barotrauma.Plugins;

namespace MyAwesomeMod;

// 1. Идентификаторы сетевых заголовков
public enum ModNetHeader
{
    ClientPing,
    ServerPong
}

// 2. Структуры пакетов данных (сериализуются автоматически движком)
[NetworkSerialize]
public readonly record struct PingData(string Note, int Timestamp) : INetSerializableStruct;

[NetworkSerialize]
public readonly record struct PongData(string ServerName, bool IsOk) : INetSerializableStruct;

public static class NetworkManager
{
    public static void Register()
    {
        var net = PluginServiceProvider.GetService<IGameNetwork>();
        net.RegisterNetworkHeaders<ModNetHeader>();

#if SERVER
        // Сервер слушает Ping от клиента и отвечает Pong
        net.RegisterHandler<ModNetHeader, PingData>(ModNetHeader.ClientPing, (data, client) =>
        {
            Plugin.DebugConsole.NewMessage($"Сервер получил пинг от {client.Name}: {data.Note}");
            net.SendToClient(client, ModNetHeader.ServerPong, new PongData("Europa Alpha Server", true));
        });
#elif CLIENT
        // Клиент слушает Pong от сервера
        net.RegisterHandler<ModNetHeader, PongData>(ModNetHeader.ServerPong, (data) =>
        {
            Plugin.DebugConsole.NewMessage($"Клиент получил ответ: {data.ServerName}, Статус: {data.IsOk}");
        });
#endif
    }

    // Отправка с клиента на сервер
    public static void SendPingToServer()
    {
#if CLIENT
        var net = PluginServiceProvider.GetService<IGameNetwork>();
        net.Send(ModNetHeader.ClientPing, new PingData("Hello from player", (int)Timing.TotalTime));
#endif
    }
}

Настройки мода в интерфейсе игры (ISettingsService)

Автоматическое добавление переключателей и слайдеров в меню настроек игры с синхронизацией по сети.

using Barotrauma;
using Barotrauma.Networking;
using Barotrauma.Plugins;

public static void SetupModSettings()
{
    var settings = PluginServiceProvider.GetService<ISettingsService>();

    // 1. Булев чекбокс
    settings.RegisterSetting(new BooleanSetting("enable_custom_hud".ToIdentifier(), defaultValue: true, label: "Включить кастомный HUD")
    {
        ShowInUI = true,
        ToolTip = "Включает информационные виджеты плагина на экране",
        SyncMode = SettingSyncMode.ClientPermissiveDesync // Настройка индивидуальна для каждого клиента
    });

    // 2. Слайдер множителя урона (авторитет сервера)
    settings.RegisterSetting(new FloatSetting("damage_multiplier".ToIdentifier(), defaultValue: 1.0f, label: "Множитель урона")
    {
        ShowInUI = true,
        UseSlider = true,
        Range = (0.5f, 5.0f),
        StepValue = 0.5f,
        LabelFunc = val => $"{val:0.0}x",
        SyncMode = SettingSyncMode.ServerAuthority, // Только хост/сервер решает значение
        IsAllowedToSet = (setting, client) => client?.Permissions.HasFlag(ClientPermissions.ManageRound) ?? true
    });
}

// Чтение значения в коде:
float mult = PluginServiceProvider.GetService<ISettingsService>()
    .RetrieveSetting<FloatSetting>("damage_multiplier".ToIdentifier())?.Value ?? 1.0f;

Собственные XML-префабы (IContentFileRegistrar)

Определение совершенно новых сущностей (квесты, фракции, рецепты), загружаемых движком через filelist.xml.

// 1. Класс префаба
public class RelicPrefab : Prefab
{
    public static readonly PrefabCollection<RelicPrefab> Prefabs = new();
    public int AncientPower { get; }

    public RelicPrefab(ContentFile file, ContentXElement element) 
        : base(file, element.GetAttributeIdentifier("identifier", Identifier.Empty))
    {
        AncientPower = element.GetAttributeInt("power", 10);
    }

    public override void Dispose() { }
}

// 2. Класс файла для движка
public class RelicFile : GenericPrefabFile<RelicPrefab>
{
    public RelicFile(ContentPackage package, ContentPath path) : base(package, path) { }

    protected override bool MatchesSingular(Identifier id) => id == "Relic";
    protected override bool MatchesPlural(Identifier id) => id == "Relics";
    protected override RelicPrefab CreatePrefab(ContentXElement element) => new(this, element);

}

🎨 Практический рецепт: Отрисовка HUD, оверлеев и видео через Harmony

Ловушка с GUI.Canvas: В Barotrauma GUI.Canvas — это RectTransform, а не полноценный компонент. Движок игры перед каждым кадром полностью очищает GUI.updateList. Поэтому если вы просто создадите new GUICustomComponent(..., GUI.Canvas), его методы Draw() и Update() никогда не будут вызваны движком!
Самый надёжный и высокопроизводительный способ отрисовать свой интерфейс или оверлей поверх игры — перехватить методы GUI.Draw и GUI.Update через Harmony: 

using HarmonyLib;
using Barotrauma;
using Microsoft.Xna.Framework;
using Microsoft.Xna.Framework.Graphics;

namespace MyAwesomeMod;

[HarmonyPatch(typeof(GUI), nameof(GUI.Draw))]
public static class GUIDrawPatch
{
    // Вызывается в конце каждого кадра отрисовки интерфейса (SpriteBatch уже открыт!)
    [HarmonyPostfix]
    public static void Postfix(Camera cam, SpriteBatch spriteBatch)
    {
        // Защищаем ScissorRectangle, чтобы оверлей не обрезался окнами чата или субмарины
        var prevScissor = spriteBatch.GraphicsDevice.ScissorRectangle;
        try
        {
            spriteBatch.GraphicsDevice.ScissorRectangle = new Rectangle(0, 0, GameMain.GraphicsWidth, GameMain.GraphicsHeight);

            // Отрисовка поверх всего интерфейса:
            // spriteBatch.Draw(myTexture, new Rectangle(0, 0, GameMain.GraphicsWidth, GameMain.GraphicsHeight), Color.White);
            MyCustomOverlay.Draw(spriteBatch);
        }
        finally
        {
            spriteBatch.GraphicsDevice.ScissorRectangle = prevScissor;
        }
    }
}

[HarmonyPatch(typeof(GUI), nameof(GUI.Update))]
public static class GUIUpdatePatch
{
    // Вызывается каждый кадр из главного цикла игры GameMain.Update
    [HarmonyPostfix]
    public static void Postfix(float deltaTime)
    {
        // Обновление таймеров, логики и опрос нажатий клавиш:
        MyCustomOverlay.Update(deltaTime);
    }
}
Преимущество: При выгрузке мода движок IHarmonyProvider автоматически снимает все созданные патчи, предотвращая любые утечки памяти.

Отладка и Hot Reload (применение кода на лету)

🔥 Hot Reload в Visual Studio / Rider

.NET 8 поддерживает применение изменений без перезапуска Barotrauma!

  1. Запустите игру с вашим модом (профиль "Launch Barotrauma").
  2. Если игра запущена отдельно, подключите отладчик: Debug → Attach to Process → выберите Barotrauma.exe.
  3. Вносите изменения в тело методов вашего C# кода.
  4. Нажмите иконку Hot Reload (или Alt + F10). Код обновится прямо в работающей игре!

🐛 Отладка с точками останова (Breakpoints)

Поскольку сборка мода компилирует `.pdb` файлы отладочных символов:

  • Ставьте точки останова в любом месте вашего кода.
  • При срабатывании игра встанет на паузу, и вы сможете исследовать стек вызовов, значения переменных и состояние мира.
💡

Лайфхак: Блокировка DLL в Windows при компиляции

Когда Barotrauma запущена, Windows намертво блокирует загруженные .dll файлы на перезапись, и при повторной компиляции сборщик выдаёт ошибку MSB3027: Файл занят другим процессом.
Решение без закрытия игры: В Windows заблокированную работающим процессом DLL можно переименовать (например, в MyModClient.dll.old)! После переименования вы можете сразу скомпилировать или скопировать на её место свежую версию без перезапуска всей ОС.

РАЗДЕЛ 10

Выгрузка модов и предотвращение утечек памяти

Barotrauma использует изолированные AssemblyLoadContext (Collectible). Когда игрок перезагружает моды в меню или выходит в главное лобби, старая сборка мода выгружается из памяти сборщиком мусора (.NET GC).

Три золотых правила мододела:

  1. Останавливайте потоки: Любой бесконечный фоновый поток (Thread, Task.Run, Timer), запущенный плагином и не остановленный в Dispose(), заблокирует выгрузку сборки навсегда!
  2. Отписывайтесь от событий: Если вы подписались на статические события игры (например, GameMain.OnResolutionChanged += ...), обязательно отпишитесь в Dispose().
  3. Используйте ExtraFields: Не храните постоянные ссылки на ваши C# типы в статических полях классов движка.
